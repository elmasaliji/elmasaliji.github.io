Craigslist – UX/QA Testing (Web + Mobile Web)

Fokus: Usability- und UX-Testing für einen Marketplace mit stark textlastigem Interface. Ziel ist es, Pain Points messbar zu machen (Task Success, Time-on-Task, Errors), systematisch zu bewerten (Heuristiken) und konkrete, testbare Verbesserungen abzuleiten.

Web Mobile Web Usability Tests Heuristic Evaluation Accessibility QA
Affordance

Text-lastig, wenig “click cues”

Viele Interaktionen wirken wie reine Textlisten statt klarer Buttons/Actions.

  • CTAs nicht visuell priorisiert
  • Nutzer “raten” den Startpunkt
  • Mehr cognitive load beim Scannen
Findability

Search/Filter führt nicht genug

Im Marketplace entscheidet Findability über Erfolg oder Abbruch.

  • Filter/Sort mental anstrengend
  • Location/Region nicht “instant klar”
  • Ergebnisse schwer zu vergleichen
Posting Flow

Posting Einstieg + Kategorien

Wenn Start/Guidance fehlt, brechen Nutzer früh ab.

  • CTA kann übersehen werden
  • Kategorien wirken wie “Wall of text”
  • Zu wenig Preview/Feedback
Trust

Vertrauen & Sicherheit (Perception)

Nutzer brauchen klare Signale, dass Interaktionen sicher/seriös sind.

  • Unklare “safe usage” guidance
  • Wenig Feedback bei riskanten Actions
  • Scam-prevention UX fehlt

Test Scope

  • Plattformen: Web + Mobile Web (responsive Verhalten, Tap targets, Layout)
  • In-Scope (UX): Navigation, Findability, Information Architecture, Feedback, Error Recovery, Trust
  • In-Scope (QA): UI Bugs, Broken states, Formular-Validation, State loss (filter/region), Performance “perception”
  • Out-of-Scope: Interne Moderation, Fraud-Backend, Payment/Checkout (falls extern)

Fokus liegt auf End-to-End Tasks, weil dort die größten Abbrüche messbar sind.

Test Strategy

  • Heuristic Evaluation: Nielsen-Heuristiken, Severity 0–4, Quick Wins markieren
  • Moderated Usability: Think-aloud, 5 Sessions, gleiche Tasks auf Web + Mobile Web
  • Metrics: Task Success, Time-on-Task, Error Count, Confidence (1–5), Drop-off Point
  • Exploratory UX: 3 Zeitboxen à 45 Min (Search, Listing, Posting)

Output: Findings Matrix + Prioritätenliste (P0–P2) + Regression Pack nach Fixes.

5 Test Tasks (Web + Mobile Web)

  • T1 Findability: “Finde ein Fahrrad unter 200€ in deiner Nähe und öffne ein relevantes Listing.”
  • T2 Filter + Scanning: “Suche weiter, versuche Filter/Sort; wähle 2 beste Optionen (begründe kurz).”
  • T3 Listing Comprehension: “Nenne Preis, Location, Zustand, Abholung/Details – ohne lange zu suchen.”
  • T4 Contact Flow: “Starte Kontakt und formuliere eine kurze Nachricht (Verfügbarkeit + Abholung).”
  • T5 Posting Flow: “Erstelle einen Post: ‘Stuhl’, 25€, Beschreibung, Location, optional Bild; korrigiere einen Fehler.”

Gleiche Tasks auf Desktop und Mobile Web, um Unterschiede in Tap/Scroll/Readability zu sehen.

Usability Test Plan (Kurz)

  • Sessions: 5 Teilnehmer, 30–35 Minuten, moderated + think-aloud
  • Protokoll: Notizen pro Task (Start, Friction, Errors, Completion)
  • Nachfragen: “Was erwartest du hier?”, “Was hat dich irritiert?”
  • Output: Findings + klare Recommendations

Regression Pack (nach Fixes)

  • R1: T1 Search + Region: klare Anzeige + stabiler State
  • R2: T2 Filter apply/reset: chips sichtbar, reset funktioniert, kein state loss
  • R3: T3 Listing readability: scannable on mobile web (no zoom needed)
  • R4: T4 Contact: clear feedback + safe guidance
  • R5: T5 Posting: Kategorien schneller, Fehlertexte konkret, back/undo ohne Datenverlust

Mini Automation (Smoke – nur Guardrails)

Diese Checks sind bewusst generisch, damit sie UI-Änderungen überleben.

// Pseudo-code (UI smoke)
test('search is discoverable on web and mobile web', async ({ page }) => {
  await page.goto('/');
  await expect(page.locator('[data-test=search-input]')).toBeVisible();
});

test('filters show applied state and can reset', async ({ page }) => {
  await page.goto('/search');
  await page.fill('[data-test=search-input]', 'bike');
  await page.click('[data-test=search-submit]');

  await page.click('[data-test=filter-open]');
  await page.fill('[data-test=filter-max-price]', '200');
  await page.click('[data-test=filter-apply]');

  await expect(page.locator('[data-test=filter-chip-max-price]')).toBeVisible();
  await page.click('[data-test=filter-reset]');
  await expect(page.locator('[data-test=filter-chip-max-price]')).toHaveCount(0);
});
